IBM webMethods Adapter for SSH Documentation

Connection Properties

Configure Host Name, Port, Authentication Method (Password or Public Key), Host Key verification policy, and Max Concurrent Channels (default 8; keep it at or below the server's own limit, OpenSSH MaxSessions defaults to 10).

Adapter Services

  • ExecCommand: Execute shell commands over SSH channel.
  • SftpList: List remote directory contents, optionally filtered by a glob, recursive, and with or without hidden entries.
  • SftpGet: Download file over SFTP.
  • SftpPut: Upload file over SFTP atomically.
  • SftpStat: Read size, times, permissions and type of a remote path (optionally without following a symbolic link).
  • SftpExists: Check whether a remote path exists and what type it is.
  • SftpRealPath: Resolve a remote path to its canonical absolute form.
  • SftpReadLink: Read the target of a remote symbolic link.
  • SftpMkdir: Create a remote directory, optionally with its missing parent directories.
  • SftpDelete: Delete one remote file or symbolic link (never a directory).
  • SftpRmdir: Remove a remote directory; with recursive true, everything below it too (refuses /, . and .., never follows symbolic links).
  • SftpRename: Rename or move a remote path; an existing target is replaced only when overwrite is true, and a directory is never replaced. Rename never creates folders: a missing target folder fails with a message naming it, unless createParents is true.
  • SftpSymlink: Create a symbolic link on the server.
  • SftpChmod: Change permission bits; permissions is octal, for example 640 or 0755. With recursive true the whole tree is changed: files get permissions, directories get directoryPermissions (empty = the file mode plus the execute bit wherever read is set, so 640 gives 750); symbolic links are skipped, never followed. Output changed is the number of entries changed.
  • SftpChown: Change the owner and/or group, by name (userName, groupName) or by number (uid, gid); give either the name or the number for the same account, not both. A name is looked up on the server first (getent, else /etc/passwd or /etc/group), because SFTP itself carries numbers only; accounts known only to LDAP/SSSD need getent. A blank owner or group is left unchanged. With recursive true the whole tree is changed; symbolic links are skipped, never followed. Output changed is the number of entries changed.
  • SftpSetTimes: Set the modification and/or access time, in seconds since 1970-01-01 UTC.
  • SftpTruncate: Set the size of a remote file; size is required, send 0 to empty the file.
  • RunShellScript: Drive an interactive login shell. The script (one step per line) is sent line by line and the service waits for the prompt, recognised by the regular expression promptPattern (for example [$#>%] $), after each. Shell state such as the working directory survives between lines. timeoutSeconds is the wait per step, not for the whole script. A pseudo-terminal is requested by default (allocatePty), because a shell prints its prompt only on a terminal; the output then contains the typed lines (echo) and, with some shells, terminal control sequences. lineEnding is LF, CR or CRLF. Output: transcript, steps (input, output, matched), stderr, completed, timedOut, closedByServer, truncated. A timeout, a shell that ends or reaching the memory limit stops the script and is reported in these fields, not thrown. This is a last resort when ExecCommand is not available and is fragile: the first run against a new target usually needs a tuned prompt pattern.
  • StartSubsystem: Start a named SSH subsystem (for example netconf), send it one request (input or inputBytes) and return its answer (output, outputBytes). Without expect the input is followed by an end-of-input signal and the answer is read until the server closes the channel; with expect (a regular expression matched against the bytes one-to-one, for example \]\]>\]\]>) the channel stays open until the pattern shows up. Output also has matched, closedByServer, timedOut, truncated and, when the server reported one, exitStatus. A subsystem the server does not offer fails with CHANNEL_FAILED. Only one request and one answer per call; a multi-turn conversation is not supported.
  • ScpUpload: Upload a local file or directory tree (localFilePath), or the bytes / content input, with SCP to remotePath. Use it for servers that offer SCP but not SFTP; prefer SftpPut when SFTP is available. A local directory is refused unless recursive is true. SCP does not create missing parent folders. A directory uploaded to a remote path that does not exist is copied into a new directory of that name; uploaded to an existing directory it is created inside it under its own name, so repeating the same upload nests the second copy. Output: remotePath, bytesWritten.
  • ScpDownload: Download remotePath with SCP to localFilePath, or, when no local path is given, one file into memory (bytes, content, limited by the connection's in-memory limit). A remote directory is only downloaded when recursive is true (default false: the server refuses it with 'not a regular file' and nothing is created locally), and then only to a local path; if the local path already exists as a directory the download lands inside it. Output: bytes, content, bytesRead, localFilePath.

Host-key services (Integration Server services)

These two are ordinary Integration Server services in the folder wm.adapter.wxssh.admin, not adapter services, because they have to work before a connection exists.

  • getHostKeyFingerprint: Connect to host (port default 22, timeoutSeconds default 10) without logging in and return the offered key: algorithm, fingerprint (SHA256:...) and knownHostsEntry. Compare the fingerprint with one you got from the server's administrator before trusting it.
  • addToKnownHosts: Add that key to the knownHostsPath file. expectedFingerprint is required: the key is fetched again and nothing is written unless it matches. The file and its folders are created when missing; an identical entry is left alone (added = false); a different key of the same type already listed for the host is refused, never overwritten. Then use the KNOWN_HOSTS host-key policy with that file.

Notification: RemoteDirectoryPoll

Watches Directory on the server and publishes one document (path, name, directory, size, modifiedSec, contentSkipped, and with Include Content also contentBytes and content) for each new file. A file counts as new by path, size and modification time and is not delivered again unless it changes. Files younger than Minimum Age are left alone; with Stability Check (default on) a file is only taken when its size and time are unchanged on two consecutive runs. After delivery the file can be left, deleted, renamed (suffix) or moved (directory; an existing file there is never overwritten). Delivery is at least once. The record of delivered files is a local file (State File), so in a cluster enable the notification on one node only.
